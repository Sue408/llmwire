# ADR-0002：请求级有界对象

> 状态：接受　|　日期：2026-09-14

## 背景

`Converter` 可以是无状态纯函数集合，也可以是跨请求长生命周期对象。LLM 流式转换需要 block index、arguments 缓冲、usage 补丁等**过程状态**。

## 决策

`Converter` 为**请求级对象**，在单次请求内同时负责请求转换与响应转换（流式或非流式），构造于请求到达、销毁于响应发完。它持有请求上下文（解码后的 `Conversation`、`StreamState`、分帧缓冲、`Report`），但**不跨请求存活**。

## 理由

1. 上述状态本质是**协议事件状态**，不是会话状态；连接一断即可整体丢弃。
2. 响应编码常需请求侧信息（Anthropic 必填 `max_tokens`、`n` 候选数、是否带 tools、`include_usage`），随对象携带最自然。
3. 与 LiteLLM / New API 的实践一致：它们的转换层状态也只存在于单次调用内；"有状态"都在控制面。

## 后果

- 对象生命周期 = 单次转换任务，符合 INV-6。
- host 每请求创建一个对象；代价是每请求一次堆分配 + dyn 分发，本地网关可忽略。

## 备选与否决

- **无状态纯函数**：无法自然承载流式过程状态，需在 host 侧外挂 FSM，违背"host 不重写硬坑"。
- **跨请求共享对象**：引入会话状态，明确违反 INV-6。
